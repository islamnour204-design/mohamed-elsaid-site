AI infrastructure

One request, from the data centre to a single multiplication

Where an AI answer is actually made

Every answer from a language model comes out of a server, a processor and, at the bottom, matrix arithmetic. At Intel I size and test that infrastructure on Xeon processors with AMX, the matrix engine inside their cores.

Data centre

Prompt
In one sentence, what is live migration?
Answer
…
  1. Data centre The request arrives over the network. A load balancer picks a server that has the model loaded and room for one more request.
  2. Rack The top-of-rack switch passes the request to that server, one of dozens in the rack.
  3. Server The model's weights sit in the server's memory. For every token it writes, a piece of text, the processor reads them again over its memory channels.
  4. Processor An AMX-capable Xeon processor: dozens of cores on one chip, linked by a mesh. The cores share the work.
  5. Core Inside each core, the AMX unit does the model's matrix arithmetic. The rest of the core runs everything else.
  6. AMX A tile of activations, the numbers the model has made from the prompt, and a tile of weights load into tile registers. The TMUL engine multiplies them and adds the result into a third tile, in one instruction: one of a great many across every layer of the model.
  7. The answer That first pass over the prompt picks the first token of the answer and keeps its working context in the KV cache. Each next token reuses that cache instead of reading the prompt again, adds to it, and reads the weights again, so memory bandwidth often sets the pace. The tokens stream back to the user.

Illustrative: a language model answering on a server with AMX-capable Xeon processors. Nothing in the drawing is a measurement; the instruction lines use simplified notation.

Research

Publications, patents, education

A decade modelling what migration actually costs

Doctorate in IT Systems Engineering at the Hasso-Plattner Institute under Professor Christoph Meinel. The thesis uses machine learning to model and predict the overhead of live migration: moving a running virtual machine from one server to another without switching it off.

  1. Copy while running. Memory is copied to the new server while the machine keeps working.
  2. Copy what changed. Pages written in the meantime are copied again, round after round.
  3. Pause and switch. A short pause copies the last pages, and the machine resumes on the new server.

Every round costs time, network traffic and, at the end, a pause. That overhead is what the research models and predicts.
